# 밸런싱

수치는 **20시즌을 직접 돌려 보고** 맞춰요. 한 시즌만 보면 운이 섞이고, 시드 하나만 보면 우연이 섞이거든요.

```mermaid
flowchart LR
  C["BalanceConfig<br/>모든 수치 한 곳"] --> R["FT.Sim audit<br/>20시즌 자동 진행"]
  R --> A["집계<br/>전력·득점·나이·재정·이적"]
  A --> D{"추세가 맞나"}
  D -->|"아니면"| C
  D -->|"맞으면"| FP["fingerprint<br/>지문으로 못 박기"]
```

## 밸런싱 하네스

수치를 건드렸으면 꼭 한 번 돌려 보세요. 기준을 벗어나면 테스트가 먼저 막아 줘요.

```bash
dotnet run --project FT.Sim -c Release -- <모드>
# 또는 빌드해 둔 exe 를 바로 실행해도 돼요
./FT.Sim/bin/Release/net10.0/FT.Sim.exe <모드>
```

| 모드 | 무엇을 보여 주나요 |
|---|---|
| `match` | 전력이 비슷한 두 팀의 3,000경기 — 득점·슈팅·홈 승률 |
| `league` | 20팀 리그 380경기 — 승점 분포와 전력이 얼마나 반영되는지 |
| `growth` | 나이별 시즌 성장과 등급별 급여 비중 |
| `world` | 세계 생성 · 일정 검증 · 등급별 전력 · 세이브 왕복 |
| `season` | 한 시즌을 실제 게임 루프로 진행 |
| `audit N` | 전력 순위와 최종 순위가 얼마나 어긋나는지, 플레이어 구단의 편차 |
| `market N` | N시즌 이적 시장 — 전력 쏠림, 구단 재정, 거절 사유 |
| `cup N` | N시즌 국내 컵 — 대진과 우승 구단 |
| `training` | 훈련 강도·중점에 따라 성장·컨디션·부상이 어떻게 맞바뀌는지 |
| `youth N` | N시즌 유스 승격과 임대 효과 |
| `savesize` | 세이브가 무엇으로 이뤄졌고, 단계마다 얼마나 드는지 |
| `room N` | N시즌 탈의실 — 화합도·불만·리더십, 분위기가 성적을 얼마나 흔드는지 |
| `venue N` | N개 시드에서 홈·원정이 몇 번씩 이어지는지 |
| `tactics N` | 전술 설정을 전부 맞붙여 보기 — 압도적인 조합이 있는지, 상성이 살아 있는지 |
| `roles N` | 역할 선택별 승점 — 관례값·최적·부적합·쏠림 비교 |
| `setpiece N` | 세트피스 — 제공권 축, 배달 방식별 기대 득점 |
| `squad N` | 개인 목표·이적 요청·국가대표 — 압력 분포와 소집 효과 |
| `recruit N` | AI 영입 안목 — 색깔 적합도, 그리고 선택이 실제로 바뀌는 비율 |
| `scout N` | 스카우트 — 추정 구간이 얼마나 넓고 얼마나 빗나가는지 |
| `staff` | 스태프 — 네 갈래의 힘, 갈래끼리의 상관, 주급 비중 |
| `wages N` | 급여 장부 쪼개 보기 — 등급·부별로 선수/스태프 주급이 수입에서 차지하는 몫, N시즌 뒤 재정 |
| `scale N` | 나라를 늘리면 세계가 얼마나 무거워지는지 — 생성·세이브·라운드 비용 |
| `names` | 이름 겹침 전수 검사 — 구단 이름·약칭·한 구단 안의 선수 이름 |
| `conf` | 대륙 대회 — 대륙마다 몇 팀이 어느 나라에서 오는지, 섞이지 않았는지, 전부 넣은 세계의 크기 |
| `ages N` | 세대 교체 — 나이 분포, 세계가 늙어 가거나 젊어지지는 않는지 |
| `honours N` | 시상·명예 — 우승 집계와 수상자 |
| `biz N` | 경기장·스폰서 — 수입 배수의 기준선 |
| `hg N` | 홈그로운 — 보유 분포, 규정에 못 미치는 구단, 이적 건수 |
| `perf N` | N시즌 동안 세계 생성·라운드·시즌 넘김·세이브 비용. **차가운 상태**(첫 실행)에서 잰 값이에요 |
| `perfround N` | 라운드 N회를 구간별로 쪼개 봐요. **충분히 데운 뒤** 표시 비용까지 같이 찍어요 |
| `fingerprint N` | 라운드 N회를 돌린 세계의 지문. 고치기 전후 값이 같으면 동작도 같아요 |
| `rollprint N` | 시즌 넘김을 N번 거친 세계의 지문(시드 셋). 플레이오프·승강을 건드렸을 때 봐요 |
| `posave <폴더>` | 플레이오프 직전 세이브 두 개를 만들어요(잉글랜드 승격 · 독일 승강). 화면 확인용이에요 |
| `perfgen N` | 세계 생성을 N회 돌려 구간별로 쪼개요(중앙값). 저장·읽기와 세이브 지문도 같이 찍어요 |
| `qe` | 품질 지수 탐색 |
| `diag` `sweep` `sens` `qref` | 상수 탐색용 |

## 수치를 고칠 때

모든 상수는 `FT.Core/Balance/BalanceConfig.cs` 한 곳에 모아 뒀어요. 코드 곳곳에 숫자를 흩어 두지 않으려고요.

잴 때는 **꼭 실제 게임 루프**(`FT.Sim audit`, `market`)로 재 주세요. 라운드만 돌리면 주간 회복·부상·성장이
빠져서 컨디션이 계속 떨어지는데, 컨디션이 골키퍼 전력에 곱해지다 보니 득점이 부풀어 올라요.
같은 상수로 돌렸는데 3.44골 대 2.77골이 나온 적이 있어요.

라인업 배치도 `FT.Core/World/LineupBuilder.cs` 한 곳에만 둬요. 게임과 측정 하네스가 서로 다른 라인업을 쓰면,
열심히 잰 수치가 실제 경기와 안 맞게 되거든요.

## 같은 시드면 정말 같은 세계가 나올까요

**같은 플랫폼 안에서만 그래요.** 시드 31415 로 38라운드를 돌린 세계의 지문이 이렇게 갈려요.

```
윈도   83b50b8b23d5d381
리눅스 51e52263589c3d19
```

> 2026-11-02 에 급여를 고치면서 세계가 달라져서 두 값을 다시 쟀어요.
> 그 전 값은 윈도 `5d6a434ee8e98c3b` · 리눅스 `4993804eda9d08fd` 였어요.

범인은 `MathF.Pow` 예요. 선수 가치(`ca^4.5`), 구단 수입(`평판^지수`), 미드필드 우위, 슈팅 질, 세트피스에
두루 쓰는데, .NET 문서에도 `Pow`·`Exp`·`Log` 같은 초월함수는 **플랫폼마다 마지막 자리에서 갈릴 수 있다**고
분명히 적혀 있어요(밑에 깔린 libm 이 달라서요). 문화권 설정 탓은 아니에요 — `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`
로 돌려도 윈도 값은 그대로였어요.

선수 가치가 1 € 만 어긋나도 AI 의 영입 판단 하나가 뒤집히고, 그 한 번이 시즌 전체를 밀어내요.
그래서 **마지막 자리의 작은 차이가 완전히 다른 세계**로 자라나요.

**플레이할 때는 아무 문제가 없어요.** 플레이어는 자기 브라우저(WASM) 안에서 세계를 만들고 그 안에서만 놀거든요.
세이브에 세계가 통째로 들어 있어서 다른 기기로 옮겨도 그대로 이어져요. 어긋날 틈이 없어요.

**문제가 되는 건 코드를 고칠 때예요.** 지문은 "고쳤는데 동작은 그대로인가"를 지키는 문지기인데,
**같은 플랫폼에서 잰 값끼리만** 비교해야 의미가 있어요. 윈도에서 고치고 CI(리눅스) 값과 비교하면 늘 다르다고 나와요.
그래서 워크플로에는 리눅스 기대값을, 이 문서에는 윈도 값을 적어 둬요.

숫자가 두 개라 좀 번거롭긴 해요. 그래도 하나로 맞추려면 `Pow` 를 직접 구현해야 하고, 그러면 20시즌을 돌려 가며
맞춰 둔 밸런스 수치를 전부 다시 잡아야 해요. 얻는 것에 비해 공사가 너무 커요.

밸런스 수치는 윈도에서 맞췄어요. 리눅스나 브라우저에서는 마지막 자리만큼 다르게 나오지만,
20시즌 집계로 잡은 값이라 그 정도 차이로 추세가 뒤집히지는 않아요.
