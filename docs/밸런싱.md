# 밸런싱

수치는 **20시즌을 돌려 보고** 맞춥니다. 한 시즌은 운이고, 한 시드는 우연입니다.

```mermaid
flowchart LR
  C["BalanceConfig<br/>모든 수치 한 곳"] --> R["FT.Sim audit<br/>20시즌 자동 진행"]
  R --> A["집계<br/>전력·득점·나이·재정·이적"]
  A --> D{"추세가 맞나"}
  D -->|"아니면"| C
  D -->|"맞으면"| FP["fingerprint<br/>지문으로 못 박기"]
```

## 밸런싱 하네스

수치를 건드렸으면 돌려 보고, 기준을 벗어나면 테스트가 막습니다.

```bash
dotnet build FT.Sim
./FT.Sim/bin/Debug/net10.0/FT.Sim.exe <모드>
```

`dotnet run` 은 이 프로젝트에서 출력이 보이지 않습니다. exe 를 직접 실행하세요.

| 모드 | 하는 일 |
|---|---|
| `match` | 동급 전력 두 팀 3,000경기 — 득점·슈팅·홈 승률 |
| `league` | 20팀 리그 380경기 — 승점 분포와 전력 반영 |
| `growth` | 나이별 시즌 성장과 등급별 급여 비중 |
| `world` | 세계 생성 · 일정 검증 · 등급별 전력 · 세이브 왕복 |
| `season` | 한 시즌을 실제 게임 루프로 진행 |
| `audit N` | 전력 순위 대비 최종 순위 오차, 플레이어 구단 편차 |
| `market N` | N시즌 이적 시장 — 전력 쏠림, 구단 재정, 거절 사유 |
| `cup N` | N시즌 국내 컵 — 대진과 우승 구단 |
| `training` | 훈련 강도·중점의 성장·컨디션·부상 거래 관계 |
| `youth N` | N시즌 유스 승격과 임대 효과 |
| `savesize` | 세이브 구성과 단계별 비용 |
| `room N` | N시즌 탈의실 — 화합도·불만·리더십, 분위기가 성적에 미치는 폭 |
| `venue N` | N개 시드의 연속 홈·원정 분포 |
| `tactics N` | 전술 설정 전 조합 맞대결 — 지배 전략과 상성 |
| `roles N` | 역할 선택별 승점 — 관례값·최적·부적합·쏠림 비교 |
| `setpiece N` | 세트피스 — 제공권 축, 배달 방식별 기대 득점 |
| `squad N` | 개인 목표·이적 요청·국가대표 — 압력 분포와 소집 효과 |
| `recruit N` | AI 영입 안목 — 색깔 적합도와 선택이 바뀌는 비율 |
| `scout N` | 스카우트 — 추정 구간의 폭과 빗나감 |
| `staff` | 스태프 — 네 갈래의 힘, 갈래 간 상관, 주급 비중 |
| `wages N` | 급여 장부 쪼개 보기 — 등급·부별 선수/스태프 주급이 수입에서 먹는 몫, N시즌 뒤 재정 |
| `scale N` | 나라를 늘리면 세계가 얼마나 비싸지는지 — 생성·세이브·라운드 비용 |
| `names` | 이름 겹침 전수 검사 — 구단 이름·약칭·한 구단 안 선수 이름 |
| `ages N` | 세대 교체 — 나이 분포, 세계가 늙거나 젊어지는지 |
| `honours N` | 시상·명예 — 우승 집계와 수상자 |
| `biz N` | 경기장·스폰서 — 수입 배수의 기준선 |
| `hg N` | 홈그로운 — 보유 분포, 규정 미달 구단, 이적 건수 |
| `perf N` | N시즌 — 세계 생성·라운드·시즌 넘김·세이브 비용. **차갑게**(첫 실행) 잰 값이다 |
| `perfround N` | 라운드 N회를 구간별로 쪼갠다. **데워질 때까지 돌린 뒤** 표시 비용까지 같이 찍는다 |
| `fingerprint N` | 라운드 N회를 돌린 세계의 지문. 고치기 전후가 같은 값이면 동작이 같다 |
| `perfgen N` | 세계 생성을 N회 돌려 구간별로 쪼갠다(중앙값). 저장·읽기와 세이브 지문도 같이 찍는다 |
| `qe` | 품질 지수 탐색 |
| `diag` `sweep` `sens` `qref` | 상수 탐색용 |

## 수치를 고칠 때

모든 상수는 `FT.Core/Balance/BalanceConfig.cs` 한 곳에 있습니다. 코드 곳곳에 흩어놓지 않습니다.

측정은 **반드시 실제 게임 루프**(`FT.Sim audit`, `market`)로 합니다. 라운드만 돌리면
주간 회복·부상·성장이 빠져 컨디션이 계속 떨어지고, 컨디션이 골키퍼 전력에 곱해지므로
득점이 부풀려집니다. 같은 상수로 3.44골 vs 2.77골이 나왔습니다.

라인업 배치는 `FT.Core/World/LineupBuilder.cs` 한 곳에만 둡니다. 게임과 측정 하네스가
다른 라인업을 쓰면, 측정한 수치가 실제 경기와 맞지 않습니다.

## 같은 시드가 같은 세계를 주는 범위

**같은 플랫폼 안에서만입니다.** 시드 31415 로 38라운드를 돌린 세계의 지문이

```
윈도   8203b42c70fa8742
리눅스 88d30e802405bb2c
```

> 2026-11-02 에 급여를 고치면서 세계가 달라져 두 값을 다시 쟀습니다.
> 그 전 값은 윈도 `5d6a434ee8e98c3b` · 리눅스 `4993804eda9d08fd` 였습니다.

로 갈립니다. 범인은 `MathF.Pow` 입니다 — 선수 가치(`ca^4.5`), 구단 수입(`평판^지수`),
미드필드 우위, 슈팅 질, 세트피스에 쓰는데, .NET 은 `Pow`·`Exp`·`Log` 같은 초월함수가
**플랫폼마다 마지막 자리에서 갈릴 수 있다**고 분명히 적어 두었습니다(기반 libm 이 다릅니다).
문화권 설정 때문이 아닙니다 — `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1` 로 돌려도
윈도 값은 그대로입니다.

가치가 1 €  어긋나면 AI 의 영입 판단이 하나 뒤집히고, 그 한 번이 시즌 전체를 밀어냅니다.
그래서 **마지막 자리의 차이가 전혀 다른 세계**로 자랍니다.

**플레이에는 문제가 없습니다.** 플레이어는 자기 브라우저(WASM) 안에서 세계를 만들고
그 안에서만 놉니다. 세이브에는 세계가 통째로 들어 있으므로, 세이브를 다른 기기로
옮겨도 그대로 이어집니다. 어긋날 자리가 없습니다.

**고칠 때 문제가 됩니다.** 지문은 "고쳐도 동작이 같은가"를 보는 문지기인데,
**같은 플랫폼에서 잰 값끼리만** 비교해야 뜻이 있습니다. 윈도에서 고치고 CI(리눅스) 값과
견주면 늘 다르다고 나옵니다. 그래서 워크플로에는 리눅스 기대값을, 여기에는 윈도 값을
적어 둡니다. 숫자가 둘인 것이 번거롭지만, 하나로 맞추려면 `Pow` 를 직접 구현해야 하고
그러면 20시즌으로 맞춰 둔 밸런스 수치를 전부 다시 잡아야 합니다 — 값에 비해 큰 공사입니다.

밸런스 수치는 윈도에서 맞췄습니다. 리눅스·브라우저에서는 마지막 자리만큼 다르게
나오지만, 20시즌 집계로 잡은 값이라 그 차이가 추세를 뒤집지는 않습니다.
