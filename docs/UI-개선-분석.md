# UI 개선 분석 — FM2024에서 배울 것과 Football Tactician에 적용할 것

- 작성: 2026-11-08, 기준 버전 v0.13.0 (`c05142c`)
- 같이 볼 것: FM 화면 하나하나의 관찰 기록은 `C:\Users\bjclo\fm24-ui-notes.md`

## 0. 어디까지 봤나

**FM2024 (레스터 세이브, 한국어, 기본 스킨이 아닐 수 있음)**
- 좌측 메뉴 18개 화면을 모두 열었다. 화면마다 첫 탭은 다 봤고, 일부 화면은 탭 드롭다운까지 펼쳤다
- 열어 본 탭은 선수 프로필 8개 전부, 스쿼드 View 전부, 전술 팀 지시 3패널, 세력 구도의 계층·만족도
- **누르지 않은 것:** 진행 버튼, 저장, 기자회견 시작, 친선경기 잡기, 예산 조정 [확인], 이적 제의, 협상 제출, 전술 값 변경
- 그래서 이적 제의 화면과 계약 조건 탭(약속 확정 이후)은 못 봤다
- 18개 화면의 하위 탭(예: 훈련의 달력·일정·선수들…)은 대부분 첫 탭만 봤다

**Football Tactician**
- `FT.App`의 레이아웃, 대시보드, 스쿼드, 선수, 전술, 계약, 받은 소식 화면 코드를 읽었다
- **브라우저로 띄워 보지는 않았다.** 아래 진단은 코드 기준이다

## 1. FM 18개 화면 요약 — 배치와 표현

| 화면 | 덩이 배치 | 정보 표현 | 드릴다운 |
|---|---|---|---|
| 홈 | 상단 3 (다음 경기, 일정, 뉴스) + 하단 3열 (순위, 탭 패널, 선수·팀 기록) | 엠블럼, 승무패 색 원, 폼 미니 막대, 순위를 말로 ("6위") | 패널 제목 `>`, 패널 `▾` 위젯 교체 |
| 수신함 | **마스터-디테일** (목록 좌, 본문 우) | 날짜 그룹, 보낸이 + 시간, 답장 필요 아이콘 | 본문 하단에 행동 버튼 ("기자회견 >") |
| 선수단 | 툴바 + 포지션 칩 + 전체 폭 표 | 색 알약 포지션, ★, 미니 폼 막대 | 이름 → 프로필, 행 우클릭 행동 메뉴, **View 교체** |
| 선수단 계획표 | **피치가 필터** (좌) + 그 포지션 선수 목록 (우) + 하단 3카드 | 포지션별 ★ 평균 | 피치 칸 클릭 → 목록 필터 |
| 세력 구도 | 상단 3카드 (결속력, 분위기, 감독 지지) + 하단 목록 | 막대 + **등급 단어**("우수") + 👍 근거 문장 | 계층 탭: **피라미드**, 만족도 탭: **색 히트맵 + 이모지** |
| 전술 | 좌 (전술 성향, 팀 지시 카드 3장) / 중 (피치) / 우 (선수 표) | 역할-임무 색 알약, 숙련도 막대 | "변경" → 피치 위에 패널이 겹쳐 열림 |
| 데이터 허브 | 레이더 차트 + 요약 글 + 번호 붙은 발견점 / 우측 보고서 타임라인 | **레이더 (우리 vs 리그 평균)** | 팀 성적 >, 선수 성적 > |
| 스탭 | 부서별 3열 (코칭, 스카우트, 의료) | 사람 아이콘 줄, 자리 채움 "1/1", 리그 최고·최저선이 그어진 막대 | 각 직원 이름, U21·U18 스탭 > |
| 훈련 | **주간 달력 격자** (요일 × 세션) + 하단 3카드 | 색 블록 + 아이콘, 요일별 강도 막대 | 블록 → 세션 상세 |
| 의료 센터 | 조언 배너 + 위험 평가 표 + 하단 (부상, 복귀) | 등급 단어 색 ("과중함", "매우 낮음"), 몸 실루엣, 빨간 위험 칸 | 선수 이름 |
| 주요 일정 | **마스터-디테일** (일정 표 좌, 경기 상세 우) | 대회별 행 색, 월 구분선, 결과 점 | 경기 → 라인업·평점 → 경기 보기 |
| 대회 | 대회별 카드 격자 | 운영진 기대 vs 성과 막대 | 카드마다 [팀 기록 >][선수 평점 >][규칙 >] |
| 스카우트 | 상단 KPI 띠 + 좌 (영입 집중 목록, 지도) + 우 (추천 표) | **추천 등급 글자 원 (A-, B+)**, 미니 피치 포지션 아이콘 | 이름, 집중 항목 > 편집 × |
| 이적 | KPI 띠 + 부대 조항 칩 + 활동 표 (전체/영입/방출) | 금액, 상태 | 담당자, 스카우트 센터 > |
| 구단 정보 | 4열 대시보드 (세부 정보, 핵심 인물, 최근 경기·전술, 명예의 전당) | 등급 단어 + ★, 트로피 수, A+ 원 | 급료 >, 재정 > |
| 구단 비전 | 목표 표 + 시즌별 탭 / 우측 운영진 평가 | 중요도 막대 + 단어, **상태 알약** (진행 중·기쁨·판단 보류) | 운영진에게 요청 ▾ |
| 재정 | 큰 면적 그래프 4개 + 우측 예산 | **시계열 면적 그래프**, 손익 0선 위아래 | 예산 조정 ▾ |
| 육성 센터 | 상단 3요약 + 주목할 선수 목록 | 성장 스파크라인 + 코치 조언 말풍선 | U21·U18 > |

**공통 틀**
- 좌측 고정 메뉴
- 화면별 상단 탭 띠. `▾`가 붙은 탭은 하위 페이지와 행동을 같이 담는다
- 타이틀 바: ← → 뒤로·앞으로, ▲▼ 같은 목록에서 이전·다음, 검색, 화면 제목 + 한 줄 부제
- 상태를 알리는 진행 버튼: 처리할 일이 있으면 빨강 "답변 요망"으로 바뀌고 진행을 막는다

## 2. 내 게임의 현재 UI — 코드로 본 진단

### 지금 있는 것
- 레이아웃 `FT.App/Layout/MainLayout.razor`
  - 좌측 사이드바: 메뉴 4그룹 17개, **상태 배지**(이적 요청·불만·만료 임박 수·창구 열림·컵 생존·기자회견 대기·안 읽은 수)
  - 상단 바: 날짜, 다음 경기, 이사회 배지, 저장, **상황에 따라 바뀌는 진행 버튼**(경기 진행 / 한 주 넘기기 / 다음 시즌 시작)
- 페이지마다 같은 틀: `h1` + 회색 부제 + `card` 묶음. 정보는 `stat` 타일, `ft` 표, `bar` 막대
- 표기 규칙은 `FT.App/Components/Ui.cs` 한 곳에 모여 있다 (포지션 색, 금액, 사기 단어 등)

### 잘 된 것 — 유지
| 항목 | 이유 |
|---|---|
| 협상 테이블 `Components/ContractTable.razor` | 항목마다 **상대 요구 / 내 제안 / 모자람·충분·넉넉함 배지**가 붙고, 슬라이더를 움직이면 바로 다시 계산된다. **FM보다 투명하다** (FM은 약속 단계에서 항목별 반응이 없고 전체 게이지만 있다) |
| 전술 지시 옆 trade-off 문장 (`Pages/Tactics.razor`의 `trade`) | "공을 더 쥐지만 다리가 더 빨리 지칩니다" 같은 대가 설명은 FM에 없다. 배울 사람에게 큰 장점 |
| 메뉴 배지 | FM의 "처리할 일" 신호와 같은 구실을 이미 한다 |
| 진행 버튼 분기 | FM의 상황별 진행 버튼과 같은 발상 |
| `Ui.cs` 한 곳 표기 | 표현 방식을 바꿀 때 한 군데만 고치면 된다. 아래 개선들의 발판 |

### 끊긴 길 — 사용자가 말한 문제의 실제 위치
1. **구단 페이지가 없다.** 라우트 목록에 `/club/{id}`가 없고, 구단 이름은 어디서도 링크가 아니다 (순위표, 일정, 대시보드 다음 경기 모두 글자만)
2. **선수 화면에서 할 수 있는 일이 없다.** `Pages/PlayerPage.razor`의 버튼은 맨 아래 "스쿼드로 돌아가기" 하나뿐이다
   - 재계약하려면 계약 메뉴로 가서 표에서 다시 찾아야 한다
   - 이적이나 임대도 각자의 메뉴로 따로 가야 한다
   - FM은 같은 행동을 선수 프로필의 탭 ▾와 스쿼드 행 우클릭 두 곳에서 다 연다
3. **받은 소식이 막다른 곳이다.** `InboxItem`(`FT.Core/World/GameWorld.cs:298`)은 날짜·제목·본문·종류·읽음만 갖고 있어서, "부상", "이적 요청" 소식을 눌러도 해당 선수나 화면으로 가지 못한다
4. **스쿼드 행에는 '열기' 하나만 있다.** 행을 클릭하면 프로필로 가는 것뿐, 행에서 바로 하는 행동이 없다
5. **카드 → 전체 화면 링크가 일부만 있다.** 대시보드의 순위표·받은 소식·주목할 선수에는 "전체 보기"가 있지만, 다음 경기 상대·이사회 목표에는 없다

### 정보 밀도가 낮은 곳
| 화면 | 지금 | FM과 비교 |
|---|---|---|
| 선수 | 카드가 세로로 쌓인다. 능력치 2카드 (기술 11 / 신체 7 + 정신 11), 행마다 이름 + 막대 + 숫자 → 스크롤이 길다 | FM은 3열 36개 + 정보 기둥이 한 화면에 들어간다 |
| 스쿼드 | 열 14개 고정, 정렬은 `<select>` | FM은 View 16종 이상, 머리글 클릭 정렬, 포지션 칩 필터 |
| 대시보드 | 상단 stat 4개 + 카드 5개 | FM 홈은 일정·기록·상대 분석까지 한 화면에 담는다 |
| 받은 소식 | 한 줄 목록 | FM은 마스터-디테일 + 행동 버튼 |

### 기타
- `FT.App/Layout/NavMenu.razor`는 Blazor 템플릿 그대로(Counter, Weather)이고 어디서도 쓰지 않는다. 지워도 된다
- 반응형 분기는 `app.css`의 `@media (max-width: 860px)` 하나뿐이다. 화면을 빽빽하게 만들면 좁은 폭 대응을 같이 설계해야 한다

## 3. 적용안 — 그대로 / 고쳐서 / 가져오지 말 것

### A. 그대로 가져올 것 (구조가 단순하고 효과가 큼)
1. **실체 링크 컴포넌트**: `<PlayerLink>`, `<ClubLink>`
   - 이름을 쓰는 모든 곳에서 이 컴포넌트를 쓰게 한다. `Ui.cs`처럼 한 곳에서 규칙을 정한다
2. **카드 제목을 링크로**: `card-head`의 `h3`가 해당 전체 화면으로 간다. "전체 보기" 버튼은 없애거나 남겨도 된다
3. **순위를 말로 같이 쓰기**: "득점 21 (리그 1위)", "실점 6 (6위)". 이미 계산할 수 있는 값이 많다
4. **목록 안 이전/다음**: 선수 화면 상단에 ◀ ▶를 두고 스쿼드 순서대로 넘긴다
